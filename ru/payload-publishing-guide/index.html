Publishing guide для редакторов Payload

Короткий чек-лист для редакторов LeadUp AI. Цикл: войти → создать или отредактировать пост → preview → publish → smoke на проде → откатить, если что-то пошло не так.

Scope: этот гайд относится к публикации в cms.leadup.guru, после которой статья попадает на blog.leadup.guru.

Source of truth: Vault-документ vault/projects/inbound-2026/deliverables/payload-publishing-guide.md.

Public URL зафиксирован для welcome-banner в Payload admin по [LEA-4357](/LEA/issues/LEA-4357).

1. Вход

  1. Открой https://cms.leadup.guru/admin.
  2. На входе будет basic-auth. Креды лежат у Алекса в 1Password Shared: LeadUp / Payload basic-auth.
  3. После basic-auth появится экран логина Payload. Используй свой email редактора и bootstrap-пароль из LeadUp / Payload editors.
  4. При первом входе смени пароль через Account в правом верхнем углу.

Если проблема только в логине, пароле, basic-auth или 1Password, это операционный вопрос: пиши Алексу, а не Мише.

2. Создание или редактирование поста

Путь в админке: Blog → Posts → Create New или клик по существующему посту.

Обязательные поля

ПолеЧто писать
TitleЗаголовок H1 статьи.
SlugURL-сегмент без кириллицы и лишних дефисов.
Localeru или en.
DescriptionMeta description + OG, до 320 символов.
ExcerptТекст для карточек и RSS, до 320 символов.
CategoryОдна из фиксированных 9 категорий блога.
Published AtДата публикации статьи.
Content Updated AtДата заметной правки; при создании равна published at.
Reading MinutesЦелое число минут чтения.
AuthorSlug автора, например vladimir-nagin.
BodyMarkdown-тело статьи. GFM-таблицы поддерживаются.

Опциональные поля

  • Tags — плоский массив строк.
  • Cover Image / Hero Image — URL или путь вида /img/....

Чего не трогать руками

  • Translation Key — по умолчанию генерируется автоматически. Для связки RU↔EN одной статьи поставь одинаковое значение в обеих карточках.
  • Published At для будущей даты лучше менять через Schedule Publish, а не вручную.
  • _status — управляется только кнопками Publish и Save Draft.

3. AEO-блоки

Заполняй их только когда действительно нужны. Пустой блок не должен вставлять JSON-LD.

БлокКогда использоватьЧто обязательно
FAQСтатья отвечает на серию вопросов.q и a для каждого пункта.
HowToМатериал является инструкцией по шагам.name, description, шаги.
EventПост анонсирует вебинар или эфир.name, startDate, location, url.

Не дублируй FAQ в markdown body, если уже заполнил его отдельным полем.

4. Preview → Publish

  1. Preview открывает черновик на блоге с параметром ?draft=1.
  2. Save Draft сохраняет черновик без публикации и без rebuild.
  3. Publish ставит _status: published и триггерит rebuild блога примерно за 30–60 секунд.
  4. Schedule Publish используй для будущей даты.

Если это уже опубликованный пост: маленькая правка → сразу Publish; большая правка → сначала Save Draft, затем финальный Publish.

5. Smoke на проде

  1. Открой URL статьи вида https://blog.leadup.guru/<locale>/<slug>. Должен быть 200 OK.
  2. Открой View Page Source и найди BlogPosting. Если заполнялись AEO-блоки, там же ищи FAQPage, HowTo или Event.
  3. Проверь https://blog.leadup.guru/sitemap.xml — нужный <loc> должен появиться.

6. Откат

  • Снять с публикации: переведи пост в draft и сохрани. Rebuild уберёт страницу с прода.
  • Versions: через вкладку версий можно откатиться на прежнюю опубликованную версию.
  • Delete: используй только как последний шаг.

Media-файлы редактор намеренно не удаляет: это защита от битых ссылок в опубликованных материалах.

7. Куда писать при проблеме

  • Контент / редактура / tone of voice: Аня или Марина.
  • Картинки / OG / дизайн: Лена.
  • Не публикуется / 404 / пустой sitemap / сломан preview: Миша. В issue приложи slug, locale, URL прода и скриншот ошибки.
  • Логин / пароль / basic-auth / 1Password: Алекс.

Важно: не правь public.posts в базе напрямую. Для редакторов канонический путь только через админку Payload.
